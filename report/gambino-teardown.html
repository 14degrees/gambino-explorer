Scenes are data, not code. Each GameScene is a JSON node tree — sprite, ninePatch, ttf, node — with properties (Position, Size, DrawOrder, Color, SpriteName) and a timeline of actions: interpolate, discrete, sequence, parallel, cubic-bezier easing. It reads like a Flash/Animate export, which is almost certainly what it is.

Asset pipeline

This is a real sequence — each step hands the next one a path.

  1. Boot picks a map.

    The client logs MapJson URL: assets/en.<quality>.<VERSION_CODE>.map.json. quality is low on a 1× display; VERSION_CODE is a global from scripts/init_common_variables.js (master_1438c33c…, app version 11.27). The map is a flat object: logical path → content-hashed path.

  2. Features load as .wad.xml packages.

    XML wrapping JSON blobs. lobby/login.wad.xml, lobby/lobby.wad.xml, lobby/LobbyMain.wad.xml on the way in; games/game117/slot.wad.xml when you open a slot. A wad declares textures, sprites, fonts, audio, video and scenes, each with hashed source paths.

  3. Textures are packed atlases.

    atlas.rgba8888.webp with a .png sibling; sprites are TexturePacker-style frame sheets (frame, sourceSize, spriteSourceSize, optional ninePatch). Multi-frame sheets are flipbooks — game117’s slot atlas carries a 27-frame fire ring.

  4. Symbol animations are video.

    Not sprite strips. Each reel symbol’s “in” animation is a VP8 .webm (MP4 fallback) whose frame is RGB on the left half, alpha matte on the right. The ids still end in .bik — Bink video from the mobile/desktop build, transcoded for web.

  5. The shader stitches it back together.

    One GLSL program compiled with defines. Under VIDEO, the fragment stage samples the same texture half a UV to the right and uses its red channel as alpha.

// packages/syd/assets/common_new.wad.xml — fragment shader, VIDEO path
#ifdef TEXTURING
  lowp vec4 color = texture2D(us_0, outCoord);
  #ifdef VIDEO
    color.w = texture2D(us_0, outCoordAlpha).x;   // outCoordAlpha = outCoord + vec2(0.5, 0.0)
  #endif
#endif
#ifdef MASK1
  color.a *= texture2D(us_M1, outMaskCoord1).x;     // up to two mask textures
#endif
gl_FragColor = color;

The game you had open

Where the catalogue comes from

Game names aren’t in the map; they arrive from the backend in one batched call, /_ah/api/batching/v1/getBatchInfo on gambino-apps.appspot.com, under response["game.getgameconfig"].rooms[].games[] — title, assetsLocation, assetsVersion, sizeType, availableFromLevel. Marketing scenes (in-app offers, avatars, compensations) are wads on a second CDN, static.gambinoslot.com/MediaLibrary/browser/en/low/…. games.json in the folder is the flattened catalogue.

Reaching it from the browser

Yes, all of it. Nothing is encrypted, signed, or behind auth; every file is a plain GET from the same public paths the client uses. DevTools → Network → filter assets/ and you watch every atlas, WebM and wad go by — 509 asset requests just to reach the lobby. The 403s you get guessing paths are only GCS saying “no such object”; the real paths are in the map.

assets.mjs in the explore folder walks the map so you don’t have to:

node assets.mjs games                # game ids in the map, by entry count
node assets.mjs list game117         # every file each of the game's wads references
node assets.mjs fetch game117 slot   # download slot.wad.xml + its webp/webm/ogg/ttf into dl/game117/

Two things to keep in mind. Each headless run creates a guest user on Gambino’s backend (their normal first-visit flow, but a write on their side), so the captures were kept to two. And the art is Spiral Interactive’s copyrighted work: study the technique and the format for the gamby wheel, don’t ship the pixels.
